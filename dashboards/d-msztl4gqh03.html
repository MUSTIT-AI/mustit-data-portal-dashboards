Summary
신규 가입자 수 = 그날 Amplitude complete_signup 이벤트를 발생시킨 유저 수(가입일=이벤트 발생일, KST).

첫구매 지표는 전부 주문DB 기준(Amplitude complete_order 이벤트는 사용하지 않음), customer_type 컬럼으로 판별합니다: "신규"=가입 당일 구매, "기존(첫구매)"=가입 후 처음 구매(오래된 회원 포함) → 이 둘을 합친 게 생애 최초 주문입니다.
· 첫구매 주문 건수 = "신규"+"기존(첫구매)" 전체 합(주문 건수 기준, 유니크 고객수 아님 — 같은 회원이 같은 날 여러 건 주문하면 건수가 중복 집계될 수 있습니다). 카드 하단에 신규가입/기존가입 비중을 나눠서 표시합니다(가입 성과인지, 오래된 회원의 구매 전환인지 구분용).
· 신규가입자 대비 첫구매 주문건수 = 당일 첫구매 주문 건수 ÷ 당일 신규 가입자 수. 동일 사용자 집단의 구매전환율이 아니며 100%를 초과할 수 있습니다(분자=그날 발생한 모든 첫구매 주문, 분모=그날 신규 가입자 — 서로 완전히 겹치는 인원이 아님). 유니크 고객 기준 정확한 전환율은 별도 RPC 승인이 필요해서 아직 준비 중입니다.
· 첫구매 주문 매출 = 첫구매 주문의 총 매출(자사 할인 제외 순매출 기준). 취소·환불된 주문도 발생 시점 기준으로 포함되어 있어 카드 하단에 취소·환불률을 같이 표시합니다. 첫구매 주문당 매출 = 첫구매 주문 매출 ÷ 첫구매 주문 건수.
· 비교값은 전주 동일요일 대비를 기본으로 강조하고, 전일·전년은 참고용으로 옅게 표시합니다(칩에 마우스를 올리면 실제 비교 대상 날짜가 보입니다). 금액은 억/만 단위로 축약 표시되며, 마우스를 올리면 정확한 값이 보입니다.
· 가입 후 구매 퍼널: Amplitude 이벤트 기준, 가입 → 상품 조회는 공통 경로, 이후 장바구니/찜 두 경로로 분기해서 각각 결제 시작 → 주문 완료까지 봄(Sankey 다이어그램, 색=경로). 유니크 사용자, 가입 후 30일 이내 전환만 집계. Amplitude API 특성상 절대 인원수를 직접 안 줘서, 신규 가입자 수 × 누적 전환율로 역산한 값입니다.
· 국가(대한민국 외 제외)와 봇/크롤러(Yeti 등, os 값 기준) 트래픽은 모든 지표에서 제외했습니다.

Cohort Summary
코호트 기준일(가입일) = 주문DB 실제 가입일(mustit_api.member_status_daily.agg_date 기준 그날 실제 가입 회원 수) · Amplitude complete_signup이 아닙니다 — Amplitude 이벤트에는 회원 식별자(member_no)가 없어서 "이 가입자가 실제로 첫구매했는지"를 회원 단위로 추적할 방법이 없기 때문입니다(데일리 탭의 "신규 가입자 수"와 이 탭의 가입자 수가 다를 수 있는 이유이며, 각각 나름의 근거를 가진 서로 다른 소스입니다).
· 첫구매 전환 = 같은 회원의 생애 최초 유효 주문(customer_type 기준, 가입 전 주문 이력이 있는 회원은 처음부터 대상에서 제외됨)이 가입일로부터 D일 이내에 발생. 유니크 회원수 기준이며, 주문 발생일(결제/배송 확정이 아닌 주문 시점) 기준입니다 — 취소·환불 여부와 무관하게 카운트되며, 첫구매 주문의 취소·환불률은 별도로 확인해야 합니다.
주의 · D7/D30 전환율은 가입 후 해당 일수가 실제로 지난 코호트만 비교 대상에 포함됩니다(아직 안 지난 코호트를 낮은 전환율로 오인하지 않도록 "집계중"으로 별도 표시, 가입자 0명이면 "N/A", 데이터 연결 실패는 "—"). "이전 동일기간 대비"도 같은 성숙도 기준으로만 비교합니다.
· 첫구매 소요일은 실제로 첫구매를 완료한 회원만 대상으로 계산합니다(미구매자는 제외) — 평균은 전체적인 속도 변화를, 중앙값·P75는 극단값 영향을 줄인 대표값입니다.
· 유입 채널·캠페인, 쿠폰, 랜딩페이지 기준 세그먼트는 주문DB에 그 정보 자체가 없어서 만들지 않았습니다(Amplitude를 붙여도 해결 안 되는 문제라 제외). 성별·연령대(주문DB 기준)는 아래에 추가했습니다 — 분모는 member_status_daily의 성별/연령대별 가입자 집계, 분자는 orders_v의 buyer_gender/age_band 기준이며 둘 다 Amplitude 없이 주문DB 데이터로만 계산합니다. "기타"(성별 미기재)/"미상"(연령 미기재)는 표본 특성상 전환율이 구조적으로 낮게 나오니 참고용으로만 보세요.
